第2～第5段階の成果物、第4段階の32体860候補、第5段階の62候補と開始時の未コミット変更は保持した。新しい候補と判断は `archive/staging/sf6-frame-data-stage6/` に保存している。本番data、DESIGN、既存の架空Fixture、依存関係、lockfileは変更していない。

## 検証基準を6項目に分離した

第5段階で全技に残した `independent_whiff_total_validation` は過剰な一律条件だったため撤廃した。原典に全体Fが明記され、対象動作と表記の意味が明確で、既知の矛盾がなければ、その原典を値の根拠として利用できる。独立資料の一致をすべての技に必須とはしない。ただし、原典の意味が不明・複数資料が矛盾・計算値しかない場合は、追加資料または実機検証を必要とする。

| 判定軸           | 確認する内容                                       | 他の判定で代用できない理由                               |
| ---------------- | -------------------------------------------------- | -------------------------------------------------------- |
| 原典との対応     | 入力・技名・状態・注記と元レコードの関係           | 同じ入力でも構え開始と反撃などが併存する                 |
| 原典の意味       | 発生、空振り全体、KD、括弧、適用対象外の意味       | 数字だけの一致では別条件を見落とす                       |
| 出題条件への適合 | 通常状態・非ホールド・派生なし、相手の姿勢や壁条件 | 条件が理解できても質問で指定できないことがある           |
| 対象パッチ       | 対象バージョンと技変更履歴の対応                   | 取得日やサイトの更新申告だけでは一致しない               |
| 独立した照合     | 別資料との一致と資料の独立性                       | 補強証拠であり、同じ転載元同士の一致は独立検証にならない |
| 収録範囲         | 原典全行の分類と未対応入力・欠落の有無             | 一部の値の正確さでは「技なし」を判断できない             |

本番化には、原典対応・意味・出題条件・パッチ・収録範囲を満たし、入力が一意でスキーマ検証に合格することを求める。条件付き値は条件を解釈できても自動で無条件の値へ変換しない。フィールドのconfirmedは保存形式の状態であり、source.verificationのverifiedとは区別する。

今回の見直しで、技単位の値・入力についてパッチ確認だけが残る候補はケン19技、マリーザ20技になった。キャラクター全体の収録範囲の認定を意味せず、これらも現時点では未検証である。技別の6軸は `review.json.characters[].moves[].criteria` に保存した。

## 奮迅脚はODと別の同時押し入力にした

既存のnormal/special区分を維持し、specialのmotionに明示的な`none`と、`buttonCombination`を追加した。

```json
{
  "type": "special",
  "motion": "none",
  "button": "K",
  "strength": "none",
  "buttonCombination": "LK+MK"
}
```

内部キーは `special:buttons:LK+MK`、表示は `KK (LK+MK)`。従来のコマンド・ODのキーとは衝突しない。motionなしには同系統の明示ペアとstrength noneを必須とし、ODやモーションありとの混在はZodで拒否する。既存データはそのまま読み込める。JSON Schemaも更新し、追加の組み合わせ制約は従来同様Zodで検証する。

UIは既存の「必殺技→コマンド→ボタン→強度」を使用し、コマンド欄に「同時押し（モーションなし）」を追加した。画面構成とCSSは変更していない。

奮迅脚の原典はKK、startupは11(9)、totalは45、ヒット／ガードは適用対象外。11(9)は攻撃発生ではなく派生受付（LK/MKは11F、HKは9F）としてconditionalにした。通常状態からの移動技を追加しただけで、派生攻撃は対象外のまま。LK+MKという操作仕様と原典KKの対応、およびパッチは未検証として残している。

ODの操作仕様はLP+MP／LK+MKを維持した。原典PP/KKの数値がその組み合わせに対応することは別に確認する必要があり、試遊でも未確認と表示する。

## 実データ試遊は開発環境で明示選択する

`npm run dev`で「未検証の実データで試遊（開発専用）」を選択すると、ケン33技・マリーザ30技を利用できる。初期選択は本番のままで、架空Fixtureとは排他的に選ぶ。画面には未検証、暫定比較対象、パッチ未確認、ODの操作仕様を表示する。フッターの出典・取得日時・CC BY-SA 4.0表示も利用できる。

本番のvalidateDatasetとresolveMoveの検証条件は維持した。開発用アダプターだけが別の検証用解決処理を使い、元データのverification、coverage、gameVersionを変更しない。開発用データはDEV条件の動的importで読み込み、通常ビルドではJSONと選択項目を除外する。ビルド後の検査とpreview画面で除外を確認した。

| 検証モードの結果       | 表示・消費ルール                                           |
| ---------------------- | ---------------------------------------------------------- |
| 原典候補あり           | 未検証と明記。通常は4項目、発生のみは発生だけ。1回記録     |
| 条件付き値             | 元表記と条件を併記。条件を無視して単一数値へ変換しない     |
| 不明値                 | 「不明」。0を代入しない                                    |
| 原典の対象範囲で技なし | 原典全行の分類に基づく。現行パッチでの不存在は未確認と明記 |
| 未収録                 | 原典での技なしと区別し、データ未収録と表示                 |
| 同一入力の衝突         | 候補を自動選択せず、質問を消費しない                       |

検証モードでは条件付き・不明・未収録も1回として記録し、5回で回答へ進む。本番・架空Fixtureのunknownを消費しない挙動は変更していない。検証モードの技なし一覧は試遊に使う入力についてだけ生成しており、任意の未知コマンドに不存在を推定しない。

## 残り30キャラへの展開

同じ6軸で技別判断を保存し、原典全行を分類してから入力を拡張する。明確な全体Fは原典を根拠に扱い、複合表記や矛盾のある項目だけ追加照合する。変更履歴との照合は、取得日で一括認定せず変更された値を優先する。

試遊対象の追加は検証用候補と原典範囲での技なし一覧を生成して行う。本番化は別途パッチ・入力・出題条件・収録範囲を認定してから判断する。現段階ではケン・マリーザも本番化できず、試遊で動作したことを性能値の検証済み判定には使わない。
