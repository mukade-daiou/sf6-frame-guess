# 第10段階：個人用データ採用と通常ゲームへの統合

2026-11-06実施。**ケン・マリーザの2体を通常ゲームへ統合した。** Fixtureや開発用試遊を選ばず、通常の本番ビルドで最初から最後まで遊べる。原典対応を基準に採用した個人用データであり、公式パッチ照合・実機測定による検証済みデータとは表記しない。

第2～第9段階の保存資料、既存の32体860候補、63候補、手動チェック表は保持した。残り30体の候補は変更していない。開始時に存在した第9段階の未コミット変更も保持している。commit・push・デプロイは行っていない。

## 採用と信頼性を分離

CharacterとMoveへ任意のadoption（accepted／held、basis）を追加した。source.verificationは従来どおり出典の確認状態として保持する。両者を別々に判定し、sourceがunverifiedでも明示的にacceptedならゲームに利用できる。

| 項目                                       | 初期採用データの状態        |
| ------------------------------------------ | --------------------------- |
| Character／Move.adoption                   | accepted                    |
| 原典一覧に基づくcoverage.status            | normal・specialともcomplete |
| source.verification／coverage.verification | unverifiedを保持            |
| gameVersion                                | UNVERIFIEDを保持            |
| datasetId                                  | initial-2026-11-06          |
| updatePolicy                               | manual                      |

coverage completeは採用した原典一覧の対象範囲を収録したことを意味し、全パッチ・全条件での網羅性や公式検証を意味しない。技なしも採用データセット内での不存在に限定した。入力が衝突すればambiguous、通常状態の判断が保留の技やheldの技はunknownで、質問を消費しない。

adoptionのない過去のステージングは自動採用しない。架空Fixture等の既存データには従来のverified判定を残し、互換性を維持した。既知の異なるgameVersionの混在、重複ID、スキーマ違反のチェックも維持している。

第7段階の標準条件による値と第8段階の原典対応・全行分類を利用した。数値を再収集・推測・計算補完していない。今回の入力キー衝突は0、通常状態が不明で追加保留にする技も見つからなかった。

ODはLP+MP／LK+MKを基本とする新方針で採用した。指定ペアによる実機計測を完了したという意味ではない。ボタン組み合わせで明確に別性能になる入力は個別に選別する設計を維持した。奮迅脚はmotion none・LK+MKで、ODとは別キー。スクトゥムも構え移行自体を採用し、自動反撃や構え中派生を混ぜていない。

## 不明値と保留を維持

次の4項目は標準条件との対応が未確定のため、不明を保持した。

| 技                   | 不明項目           | ゲームへの影響                                                 |
| -------------------- | ------------------ | -------------------------------------------------------------- |
| ケン2HK              | 空振り全体F        | 通常モードは非消費。発生のみは利用可                           |
| ケンOD龍尾脚         | 立ち相手への発生F  | 発生が表示できる技が必要な入力候補一覧では保留。レコードは保持 |
| マリーザ2MK          | 空振り全体F        | 通常モードは非消費。発生のみは利用可                           |
| マリーザODクアドリガ | 中央でのヒット結果 | 通常モードは非消費。発生のみは利用可                           |

技のレコードを持つことと、その値が表示できることを分離した。unknownを0やD、括弧から推定した範囲へ変換していない。確定範囲の表示、ダウンD、非攻撃技の適用対象外も維持する。必要な値が1項目でも不明ならその質問は非消費、発生のみでは他3項目の不明は妨げない。

採用データの該当カテゴリがpartialなら、未掲載入力をunknownとし、技なしに変換しない。同入力のheld・条件版が残っている場合もunknownを返す。completeな採用カテゴリで該当レコード自体がなければ、採用データ内の技なしとして1回消費する。

## 保存先と手動更新

本番データは `data/metadata.json` と `data/characters/ken.json`・`marisa.json`。`data/NOTICE`、ルートNOTICE、JSON内の出典・帰属・CC-BY-SA-4.0・取得日時を保持した。画面でも「公式検証・対象パッチは未確認」「技なしは採用データ内の不存在」と明示し、出典欄に確認状態を表示する。

採用判断は `data/adoption-decisions.json`、機械可読な統合結果は `release.json`。`scripts/build-snapshot.ts`は判断一覧を順に処理して検証・出力する。アプリは既存のglobで本番JSONを検出し、キャラIDの追記を必要としない。

```sh
# 現在の判断から検証・レポートを再生成（ネット取得なし）
npx tsx scripts/build-snapshot.ts
# 初期出力、または既存スナップショットと同一であることの確認
npx tsx scripts/build-snapshot.ts --write
```

初期データが既にある場合、通常の--writeで違う値へ上書きできない。更新には明示的なユーザー指示、新しいdatasetId、--write --updateが必要で、既存キャラを判断一覧から落とす操作も拒否する。起動・ビルド・試遊でデータを取得・更新する処理は追加していない。

残り30体を追加するときは、原典対応・状態・明確な矛盾を判断し、同じ判断一覧へ対象レコードをまとめて追加できる。不明な状態や衝突はheld／unknownにし、残っている860候補を無条件に取り込まない。更新後もUIや抽選ロジックに固定IDを追加する必要はない。

## 検証結果

型検査、Vitest31件、node:test30件、Zod2体、ローダー、本番ビルドが成功した。出典未検証でも明示採用なら2体が対象になること、未採用ステージングを自動採用しないこと、不明・保留・衝突・未収録・採用範囲での技なしを区別することを確認した。採用データの再生成一致と、過去の候補・第9段階の手動submissionが変わらないことも検証した。

第6・第7段階のテストは、以前「奮迅脚のIDが本番バンドルに一切存在しない」と判定していた。今回は正式に採用したため、そのIDだけを禁止する旧条件を取り除き、開発用データパスと開発用選択項目を除外するチェックを維持した。過去の保存データや報告書は変更していない。

```sh
npm run typecheck
npm test
npm run validate:data
npm run build
node --test --test-concurrency=1 tests/*.test.mjs
node scripts/verify-gameplay.mjs
```

ブラウザー試験は起動済みの127.0.0.1:4173の本番previewを使う。ビルドには従来のZod PURE注釈警告と、採用データ追加による500kB超のチャンク警告があるが、ビルドは成功した。今回のJSは約508kB、gzip約114kBで、依存更新や警告回避だけを目的とした分割は行っていない。

採用済み2体で通常ゲームは利用可能になった。出典の信頼性向上や4項目の不明値の調査は、今後明示的な更新指示があったときに行える。第9段階の実機チェック表は保存しているが、本番採用の必須条件にはしていない。
