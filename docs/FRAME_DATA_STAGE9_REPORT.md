3. 対象版だと確認できた場合だけ、ケンとマリーザの録画へ進む。同じ起動セッション内で撮影し、日時・タイムゾーンもメモする。

最小構成の想定は **version.png、ken-session.mp4、marisa-session.mp4の3ファイル**。キャラごとの動画内で、設定→技一覧→入力試行を続けて撮れば、動画を多数に分ける必要はない。分割録画や複数画像でも、セッションと該当時刻が分かれば受け付けられる。既存の画面キャプチャ／録画機能を使い、ゲームへ外部ツールを注入しない。

## 各キャラの録画順序

1. クラシック設定、キャラ名、入力履歴とフレームメーターが有効なことを映す。
2. ゲーム内の技一覧を全区分、最後の行まで映す。項目名・コマンド・カテゴリが読める速度でスクロールする。
3. トレーニングの通常設定で両者を画面中央、通常状態へ戻す。非ホールド・派生なし、通常ヒット/ガードにする。各試行前に位置・ゲージ・状態を初期化する。
4. チェック表の順で指定ペアを入力する。攻撃技は空振り、通常ヒット、通常ガードを分けて記録する。発生は立ち相手に初めて当たる判定と、初期の空中限定判定を区別する。下段のガードはしゃがみを例外とする。
5. 各試行の動画時刻・技名・入力ペア・観測値をメモする。読み取れなければ不明を残す。ゲーム内のフレーム表示・スロー等で確認できる場合だけ利用し、推測で数値を補完しない。

奮迅脚とスクトゥム本体は非攻撃。派生受付やアーマー開始を攻撃発生とせず、非ホールド・反撃なし・派生なしの全体を記録する。攻撃発生・ヒット差・ガード差は適用対象外として扱う。

技名が対戦HUDに表示されない場合は、先にゲーム内技一覧の技名と入力を映し、同じ入力履歴と実行映像へつなげる。観測した技名はメモにも残す。

## 保存先と次のセッションへの引き継ぎ

保存先は `staging/sf6-frame-data-stage9/evidence/`。Windowsで録画した場合は、録画後にこのフォルダーへコピーする。保存先の案内は [evidence/README.md](../staging/sf6-frame-data-stage9/evidence/README.md) にもある。

メモは [OBSERVATIONS.md](../staging/sf6-frame-data-stage9/OBSERVATIONS.md) に書く。JSONをユーザーが直接編集する必要はない。次のセッションで動画・画像とメモを確認し、Codexが `submission.json` へ転記できる。空欄は未実施、不明と適用対象外は別に記録する。

| ファイル                           | 用途                                                             |
| ---------------------------------- | ---------------------------------------------------------------- |
| plan.json                          | 63技のID・入力・未検証参照値・過去の照合・完了／未完了区分       |

| scripts/check-stage9-submission.ts | 構造・版・ファイル参照等の検査。候補・本番データは書き換えない   |

`submission.json`はsessions、observations、coverageを持つ。sessionsにはid、battleVersion（接頭辞Ver.なしの数値）、versionLabel、versionMeaning、capturedAt（UTC ISO日時）、evidenceを記録する。observationsはmoveId、observedName（実際の技名）、sessionId、inputPair、standardConfirmed、4種類のframes、evidence、notes。coverageはcharacterId、sessionId、observedMoveIds、outOfScope、unresolvedRows、evidenceを記録する。evidenceはこの保存先からの相対fileとlocator（動画時刻／画像内の位置）。

```sh
# 現在の空の提出データではpendingになる。ゲーム起動・ネット取得なし
npx tsx scripts/check-stage9-submission.ts
# 別の提出JSONを検査する場合
npx tsx scripts/check-stage9-submission.ts /path/to/submission.json
```

検査は版違い・版の意味未確認、未保存ファイル、保存先外のパス、moveIdやセッションの誤り、入力ペアの誤り、範囲不足・未分類行等を検出する。画像や動画の内容を自動検証する機能ではない。ファイルが存在し、構造が正しくてもcanPromoteはfalseのままで、内容を技単位で確認する必要がある。受領記録数と実際のゲーム検証完了数も分けている。

準備スクリプトはsubmission.jsonが既にあれば上書きしない。CHECKLISTとplanは生成物なので、手動メモはOBSERVATIONSへ残す。
